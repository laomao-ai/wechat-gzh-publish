# 配图策略

核心判断：**什么该用 AI 生图，什么不该。**

不是所有图都该丢给图像模型。

---

## 一、三类配图，各走各的路

| 类型 | 生成方式 | 理由 |
|---|---|---|
| **封面** | AI 生图 + 严格后处理 | 有设计感、有留白、文字为主 |
| **架构图 / 流程图 / 对比图** | **代码生成 SVG/HTML** | 文字必须准确、要能改、不怕重复 |
| **正文插图 / 氛围图** | AI 生图 | 无文字、看构图 |

**最常见的错误**：把架构图丢给 AI 生图。

图像模型画"架构图"的文字必然出错——因为它把图当画来画，不是当文字来写。而架构图的价值**全在文字准确**。

---

## 二、架构图 / 流程图：优先代码生成

**为什么不用 AI 生图**：
- 文字必然出错（实测："链路"第三字会变形）
- 改不动——要调层级关系就得重生成
- 不可复用——风格变化时全部重画

**怎么生成**：
1. 手写 SVG（推荐，精确、可版本控制）
2. 或用 HTML+CSS 写（适合表格型、卡片型）
3. 或用 Mermaid（适合纯流程拓扑）

**关键约束**：
- 文字用真实文本节点，不要转成路径
- 色系控制在 ≤2 个（复杂配色会变乱）
- 删到只剩必要层级——**信息密度 > 视觉规整**

**踩过的坑**：第一版把所有框画成一样大小，看着规整但信息量为零，读者扫一眼不知道看哪儿。删到只剩四层、靠位置和留白拉开重点才对。

---

## 三、封面：AI 生图 + 三件必做后处理

### 后处理清单

| 问题 | 处理 | 是否确定性 |
|---|---|---|
| 右下角「AI 生成」平台水印 | 裁掉底部约 7.5% | ✅ 脚本可做 |
| 生图默认 1:1，微信要 2.35:1 | 裁成 900×383 | ✅ 脚本可做 |
| 中文文字变形 | **严重时换方案** | ❌ 只能人工判断 |

### 裁切锚点（最容易错的一步）

**锚点选错会切掉标题。**

```
默认 anchor = 0.22   ← 从垂直 22% 处开始切
```

- `anchor=0` → 只剩标题上半，标题被切
- `anchor=0.22` → 保住主标题 + 副标题 ✅
- 上限不能超过 `1 - band_height/H`

```bash
python3 scripts/fit_cover.py 生图产物.png -o cover-900x383.jpg --anchor 0.22
```

**务必目视检查成品。** 这一步脚本无法判断。

### 提示词写法

用 `config/brand_voice.json` 里锁定的 `cover_prompt_style`，**逐字复用**，只改标题文字。

风格描述段要包含：
- 版式风格（瑞士国际主义 / 编辑杂志 / 极简）
- 背景（纯白）
- 主色及其占比约束（"不超过三分之一"）
- 标题字号层级（大标题深炭灰，次标题中灰，小字浅灰）

**风格稳定性来自收窄选择空间，不来自"每次生成得更好"。** 禁止每篇重新描述视觉风格——那是风格漂移的根源。

## 四、封面质量判断标准

生成后过这四关：

- [ ] **无水印**（角落干净）
- [ ] 比例合规（900×383，2.35:1）
- [ ] 标题完整不截断
- [ ] 中文无明显变形

**中文变形怎么办**：
- 轻微 → 可接受，读者不会逐字看
- 严重（错字、笔画粘连）→ **改用无文字封面**：纯色块 + 几何图形，或纯图形封面。文字放到排版层做

**别死磕生图**。封面是入口，读者停留 1 秒，不需要多精致。

---

## 五、正文插图策略

### 该生图的情况
- 氛围图、场景图、需要情绪表达的
- 抽象概念的可视化（不涉及精确文字）
- 封面延伸系列图

### 不该生图的情况
- 任何包含准确中文标签的图
- 数据图表（**用代码生成**，数值必须对）
- 架构/流程（见上）
- 对比表格（**用 HTML 表格**，排版层能处理）

### 尺寸约定

| 用途 | 尺寸 |
|---|---|
| 公众号封面 | 900×383（2.35:1） |
| 公众号分享卡 | 1024×1024（1:1） |
| 正文横图 | 1536×1024 |
| 正文竖图 | 1024×1536 |

注意：多数模型只支持固定档位（1024×1024 / 1536×1024 / 1024×1536），靠 `fit_cover.py` 裁到目标比例。

---

## 六、模型选择：封面 vs 插图

**封面**：中文文字为主 → 对模型中文能力敏感。可先用宿主 Agent 自带能力，变形明显再切外部 API。

**插图**：无文字、看构图 → 模型能力差异影响小。

### 是否需要接外部 API

**先别接。** 宿主 Agent 通常自带生图能力（能省一份 Key + 一份账单）。

需要接的情况：
- 云端 Agent 无生图能力
- 要批量稳定出图

Provider 配置见 `config/image_providers.json`：

```bash
python3 scripts/gen_image.py list    # 看当前可用
python3 scripts/gen_image.py check   # 体检
```

优先级：`auto_delegate`（宿主自生）→ 已配置的外部 API。

**架构图永远不用生图。** 这条不管用什么模型都一样。

---

## 七、配图的反模式

| 别做 | 为什么 |
|---|---|
| 生图生成架构图 | 文字必然错 |
| 生图生成数据图表 | 数值必然错 |
| 每篇换风格重写提示词 | 风格漂移 |
| 为"配图完整"给每段配图 | 图不是越多越好 |
| 用外部图床托管正文图 | 微信只认自己域名 |
| 封面带文字却不检查变形 | 首图质量决定跳出率 |

**判断标准**：这张图如果文字是核心信息，就必须代码生成或人工制作。
