# 标题优化

**定位：给候选 + 打分 + 说理由。不替用户拍板。**

标题是最主观的一环，所以这个能力的输出是**一组排序好的选项**，最终选哪个由用户定。

---

## 一、三条通用规律（有依据，不是玄学）

### 1. 长度落在 14～24 个字

这不是拍脑袋。基于公开的公众号爆款标题样本统计：

- 平均约 20.9 字
- 中位数约 19.5 字
- **80% 以上不超过 24 字**

超过 28 字就开始被折叠或读起来费劲。信息完整的前提下，**越短越好**。

### 2. 关键词放前半段

让读者和平台都能快速识别主题。

- 一个标题**只保留一个核心关键词**，最多两个
- 优先选文章真正围绕的实体、技术名或场景词
- **不要为蹭热度加入正文无关的词**

### 3. 事实红线（最重要）

> 标题里的每个事实，正文必须能兑现。兑现不了就改标题。

| 标题说了 | 正文必须 |
|---|---|
| 「省了 3000 块」 | 真有这笔账，能算清 |
| 「跑了 7 天」 | 真有 7 天的过程 |
| 「开源了」 | 真能访问到代码 |

**这条优先级高于所有其他评分维度**——事实不成立，直接淘汰，不靠其他分补偿。

因为标题虚的代价是长期毁账：单篇有点击，读者信任会被透支完。

---

## 二、生成流程

### Step 1 提取六要素

从正文里找：

1. **核心实体** —— 品牌、产品、技术、人物、事件
2. **最强变化** —— 替代、反转、崛起、风险、新机会
3. **最强结果** —— 省时、赚钱、增长、可带走的东西
4. **最强证据** —— 亲测、耗时、数字、真实经历
5. **读者痛点** —— 他为什么点进来
6. **主情绪** —— 从正文找，不能编

第 6 项必须来自正文。正文支撑不了的强度，标题不许有。

### Step 2 生成至少 20 个候选

- 必须**实质不同**，不是换近义词
- 覆盖 **4 种以上点击动机**
- 同一开头或同一收尾骨架，最多出现 2 次

### Step 3 打分排序

| 维度 | 建议权重 | 判什么 |
|---|---|---|
| 点击欲与情绪 | 30 | 有没有变化 / 冲突 / 收益 / 损失 / 好奇 |
| 事实与具体性 | 25 | 有没有正文可证的证据 |
| 关键词自然度 | 20 | 主关键词是否自然嵌入 |
| 简短清晰 | 15 | 长度与断句是否利落 |
| 风格匹配 | 10 | 像不像真人说话 |

**权重是建议值，可调。** 比如带情绪的话题可以把第一项提到 40。

### Step 4 输出

```
首选标题：1 个
备选标题：3～5 个，按推荐顺序
关键词：主关键词 + 可选次关键词
首选理由：一句话说清爆点（不展示内部打分过程）
```

**不要输出打分表**——用户要的是能用的标题，不是分析报告。除非他明确要。

## 三、六类结构（探索方向，不是填空模板）

方括号是变量，**不要出现在最终标题里**。

**实体变化型**
```
再见[旧工具]，[新产品]出手了
[关键词]的第一波[变化]出现了
```
前提：正文真的支持"替代"或"影响出现"

**亲测结论型**
```
试了下[产品]，回不去了
用[关键词]做[场景]，太丝滑了
```
前提：结论来自真实体验

**个人实战型**
```
我用[关键词]搭了[成果]
我把[成果]开源了，[痛点]解决了
```
前提：作者真的做过

**投入证据型**
```
爆肝[时间]，我把[成果]开源了
耗时[时间]，我们做了[交付物]
```
前提：数字是证据，不是装饰

**好奇冲突型**
```
一个被严重低估的[关键词]
[群体]，已经没有秘密了
```
前提：标题制造的问题，正文得回答

**教程交付型**
```
[关键词]国内也能用，亲测有效
我把[关键词]实战指南开源了
```

## 四、情绪钩子（可选，按需启用）

**先判断正文主情绪，再用具体场景承接。**

| 情绪 | 句式方向 | 前提 |
|---|---|---|
| 不平 | 凭什么… / 太离谱了… | 后半句接可验证的落差 |
| 反转爽 | 原来…这么简单 / 我终于… | 正文已给出结论 |
| 焦虑避坑 | 这几个坑别踩 / 再不…就晚了 | 正文能证明损失或时效 |
| 对比落差 | 同样…，凭什么… | 对比对象真实存在 |
| 共鸣 | 原来不只我一个人… | 情绪来自真实经历 |

**规则**：
- 情绪钩子优先放**前半句**或形成明显转折
- 只在句尾加"回不去了""有点猛"这类词，**不算情绪钩子**
- 句尾口语只负责释放情绪，不能单独当爆点
- 情绪强度不能超过正文证据

## 五、淘汰清单

这些不是"不好"，是**没信息**：

```
✕ 重磅！某某产品震撼发布，彻底改变行业格局      ← 通稿味，判断空洞
✕ AI 时代如何提升工作效率？                    ← 无识别实体、无证据
✕ [产品] 功能全方位深度解析                     ← 关键词堆砌
✕ 某某新工具上线了，功能非常强大                  ← 只有形容词
✕ 我发现了一个超级好用的工具                     ← 套谁都行
```

**重写规则**：补足「对象 + 变化或行动 + 具体结果」，删掉不影响点击决策的背景词。

---

## 六、符号与格式

| 规则 | 说明 |
|---|---|
| 默认只用一个中文逗号 | 连接两个短分句 |
| 结尾可用一个 `！` | 不要多个 |
| **默认不用** | 句号、冒号、分号、括号、方括号、引号、竖线、斜杠、破折号、Emoji、话题标签、连续标点、省略号 |
| `？` 例外 | 仅当文章明确回答一个高价值问题时 |
| `+` 例外 | 仅当工具组合本身就是核心关键词时 |

产品名、版本号里的 `.` `-` `+` 保留官方写法，不额外添加。

---

## 七、用户优先（重要）

**本文件的规则是默认建议，不是硬约束。**

- 用户明确要求某个方向 → 直接照做，规则让位
- 用户说"就要长标题" → 给长的，但提示一下折叠风险
- 用户的账号已形成风格 → 以他的风格为准

**规则的目的是给一个不会太差的下限，不是规定上限。**

---

## 怎么把它用得更好

**用自己的样本替换通用规律。**

上面的长度区间和结构分类来自公开的爆款标题统计，是个不错的起点。但**你自己的数据永远比通用规则准。**

做法很简单：

1. 收集你自己阅读量最高的 20～30 篇标题
2. 统计它们的长度分布、常用结构、高频词
3. 替换掉第三节的六类结构，换成你自己的分类

改完之后，这套标准就是为你账号定制的了。
